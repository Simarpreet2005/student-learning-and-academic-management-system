Thank you for your interest in contributing to Academic LMS! Contributions help improve the project and make it more useful for students, lecturers, parents, and administrators.

Whether you are fixing bugs, improving documentation, adding features, or suggesting enhancements, your contributions are welcome.

Please review the following guidelines before contributing.

## Code of Conduct

Be respectful, constructive, and professional when interacting with other contributors. Help maintain an inclusive environment where everyone can participate and collaborate effectively.

## Getting Started

Before contributing, set up Academic LMS on your local machine.

1. Read the project's `README.md` for installation and setup instructions.
2. Fork the repository.
3. Clone your fork to your local machine.
4. Install the required dependencies.
5. Configure the environment variables and database as described in the documentation.
6. Run the application and existing tests to verify your setup.

## How Can I Contribute?

### Reporting Bugs

If you discover a bug, open an issue describing the problem.

Please include:
- A clear and descriptive title.
- Steps to reproduce the issue.
- Expected behavior and actual behavior.
- Relevant error messages or screenshots, if applicable.
- Your operating system and relevant software versions.

### Suggesting Enhancements

Suggestions for new features and improvements are welcome.

When proposing an enhancement:
- Explain the problem it solves.
- Describe the proposed functionality.
- Explain how it benefits users.
- Include examples or implementation ideas when relevant.

Potential areas for improvement include course management, learning resources, assignments, assessments, grade management, attendance tracking, notifications, dashboards, and academic workload planning.

### Pull Requests

To contribute code or documentation:

1. Fork the repository.
2. Create a descriptive branch for your changes.
3. Implement your changes following the project's coding conventions.
4. Run the relevant tests and verify that existing functionality continues to work.
5. Commit your changes with clear and descriptive commit messages.
6. Push your branch to your fork.
7. Open a pull request against the repository's `main` branch.
8. Describe your changes and reference any related issues.

Keep pull requests focused on a specific improvement whenever possible. Include screenshots for significant user interface changes when appropriate.

## Style Guidelines

Follow these guidelines to maintain a consistent and readable codebase.

### General Guidelines

- Use consistent indentation and formatting.
- Choose clear and descriptive names for variables, functions, classes, and modules.
- Keep functions focused and maintainable.
- Add comments and docstrings where they improve clarity.
- Avoid unnecessary code duplication.
- Follow the conventions already established in the relevant part of the project.

### Python and Django

- Follow standard Python conventions, including PEP 8.
- Use Django's established patterns for models, views, forms, URLs, and permissions.
- Keep business logic organized and maintainable.
- Use migrations for database schema changes.
- Validate user input and enforce appropriate access controls.
- Write tests for new functionality and bug fixes.

### Frontend

- Maintain consistency with the existing interface and design system.
- Use reusable components where appropriate.
- Ensure forms and interactive elements provide clear feedback.
- Consider accessibility and responsive layouts.

### Testing

- Run relevant tests before submitting a pull request.
- Add or update tests when introducing new features or fixing bugs.
- Verify that changes do not unintentionally break existing functionality.
